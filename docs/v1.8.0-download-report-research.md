# v1.8.0 Download Monitor連携ダウンロードレポート調査メモ

## 調査目的

DCJ Free PDF Mailer v1.8.0 の候補機能として、管理画面の「ダウンロードレポート」セクションにPDF設定ごとのDownload Monitor集計を表示できるか調査する。

今回は実装しない。`dcj-free-pdf-mailer.php`、PDF設定、購読者データ、Download Monitor側データは変更しない。

## Download Monitor側の確認結果

確認元:

- WordPress.org plugin page: https://wordpress.org/plugins/download-monitor/
- Download Monitor公式KB: https://download-monitor.com/kb/migrate-download-counts/
- Download Monitor公式KB: https://download-monitor.com/kb/how-to-delete-logs/
- WordPress.org公式配布zip `download-monitor.latest-stable.zip` を `/tmp` に展開してソース確認

### 投稿タイプ

Download Monitorは、ダウンロード項目をWordPressのカスタム投稿タイプとして保持している。

- ダウンロード本体: `dlm_download`
- ダウンロードバージョン: `dlm_download_version`
- バージョン投稿は `post_parent` で `dlm_download` の投稿IDに紐づく
- カテゴリ: `dlm_download_category`
- タグ: `dlm_download_tag`

### ダウンロードID

Download Monitor IDとして扱うべき値は、`dlm_download` 投稿の `ID`。

ショートコードやREST/API上も、基本的にこの投稿IDを指定してダウンロードを取得する設計になっている。

### ファイルURLの保存場所

ファイルURLは主に `dlm_download_version` 側の投稿メタ `_files` に保存される。

`_files` はJSON文字列または配列として扱われ、複数ミラーURLを持てる。通常は先頭URLが代表URLとして使われる。

注意点:

- Download Monitor内部のRepository経由で取得すると、ファイルサイズが空の場合に `_filesize` を補完保存する処理が走る可能性がある。
- v1.8.0のレポート表示では、DB更新を避けるため、Repository経由の取得ではなく、`get_post_meta( $version_id, '_files', true )` など読み取り専用の取得を優先するのが安全。

### ダウンロード数の保存場所

現在のDownload Monitorでは、主に以下のテーブルが関係する。

- `{$wpdb->prefix}dlm_downloads`
  - `download_id`
  - `download_count`
  - `download_versions`
  - フロント表示、一覧、ダッシュボード等の合計ダウンロード数に使われる
- `{$wpdb->prefix}download_log`
  - `download_id`
  - `version_id`
  - `download_date`
  - `download_status`
  - `user_id`
  - `user_ip`
  - `user_agent`
  - 詳細ログ、期間別集計、最終ダウンロード日時の取得に使える
- `{$wpdb->prefix}dlm_reports_log`
  - `date`
  - `download_ids`
  - レポート画面のチャート用日別集計に使われる

公式KBでは、`download_log`、`dlm_reports_log`、`dlm_downloads` の3つがレポートとダウンロード数に関係すると説明されている。

### 日別ダウンロード数

取得候補は2通りある。

1. `dlm_reports_log.download_ids`
   - 日別集計済みのJSONを読む
   - Download Monitor本体のReports画面もチャート用に利用している
   - ただしJSON構造の互換性確認が必要

2. `download_log` を `DATE(download_date)` と `download_id` で集計
   - 生ログから直接集計できる
   - 期間指定や最終日時取得に使いやすい
   - ログが多い場合は重くなりやすい

v1.8.0の最小実装では、日別グラフまでは実装せず、合計と最終日時に絞るのが安全。

### 合計ダウンロード数

最小実装では `dlm_downloads.download_count` を読むのが第一候補。

ただし過去バージョンや手動カウントの関係で、`_download_count` 投稿メタが関係するケースがある。Download Monitor本体の一覧表示では `dlm_downloads.download_count` と `_download_count` を合算する実装が存在するため、LocalWPで実データの表示値と一致するか確認が必要。

推奨:

- まず `dlm_downloads.download_count` を表示
- 必要なら補助的に `dlm_download` または `dlm_download_version` の `_download_count` を調査
- Download Monitor本体の表示値との差異がある場合は、v1.8.0では「DLM表示値と異なる可能性あり」と備考表示するか、合算仕様を合わせる

### 最終ダウンロード日時

`download_log` から取得可能。

候補SQL:

```sql
SELECT MAX(download_date)
FROM {prefix}download_log
WHERE download_id = %d
  AND download_status IN ('completed', 'redirected')
```

Download Monitor本体のReportsでは `completed`、`redirected`、`failed` を分けて集計している。DCJの最小レポートでは、実際に配布できた可能性が高い `completed` と `redirected` を対象にする案が自然。

## DCJ Free PDF Mailerとの紐づけ候補

### 1. PDF URLで自動照合

メリット:

- 既存PDF設定に新しい入力項目を追加せずに試せる
- 手入力が不要
- 24件の既存PDFを一括で候補照合できる可能性がある

デメリット:

- DCJ側PDF URLが直接Media Library URLで、Download Monitor側が保護URLや別パスの場合は一致しない
- Download Monitorはバージョンごとに複数ミラーURLを持てるため、一意判定が難しい
- URLの正規化、エンコード差、http/https差、末尾スラッシュ差で誤判定しやすい
- Repository経由の取得で意図しないメタ更新が起きる可能性がある

評価:

- 初回実装で完全自動照合にするのは避ける。
- 将来的に「候補表示」程度なら有用。

### 2. Download Monitor IDをPDF設定に手動入力

メリット:

- 最も安全で明確
- 既存PDF設定IDやショートコードIDを変更しない
- 自動照合ミスがない
- Download Monitor側のファイルURL構造に依存しにくい
- 未連携PDFは「未設定」と表示できる

デメリット:

- PDF設定編集画面に新しい入力欄を追加する必要がある
- 24件分を管理者が確認して入力する手間がある
- PDF設定データ構造に `download_monitor_id` などの任意項目が増える

評価:

- v1.8.0の推奨方針。
- 既存設定には値が無いだけなので、既存データへの破壊的影響は避けられる。

### 3. Download Monitorタイトルで手動照合

メリット:

- URLより人間が判断しやすい
- Download Monitor IDを知らなくても候補を見つけやすい

デメリット:

- タイトル重複や表記ゆれが起きる
- 日本語/英語タイトル差、PDF設定タイトルとの違いで一致しない
- 最終的にはID確定が必要

評価:

- 実装するなら補助的な候補表示に留める。
- 主キーとしては使わない。

### 4. 将来的にPDF設定に「Download Monitor ID」欄を追加

メリット:

- 管理画面でPDF設定とDLM項目を明示的に管理できる
- レポート表示が安定する
- 自動照合機能を後から追加しても、最終的な保存値はIDで固定できる

デメリット:

- PDF設定保存配列に新しい任意キーが増える
- 入力値検証、存在確認、未設定表示が必要

評価:

- v1.8.0で実装するならこの方式が最小安全。
- 新規キーは未設定時に空文字扱いにし、既存24件は自動変更しない。

## 推奨方針

v1.8.0では「手動でDownload Monitor IDをPDF設定に入力する方式」を採用する。

基本方針:

- 既存PDF設定ID、ショートコードID、PDF URLは変更しない
- 既存24件には `download_monitor_id` 未設定として扱う
- 管理者がPDF設定編集画面でDLM IDを任意入力できるようにする
- レポートは管理画面の「ダウンロードレポート」折りたたみセクションに表示する
- Download Monitorが無効、またはテーブルが無い場合は説明文を表示するだけにする
- 自動照合は初回では実装しない

## v1.8.0での最小実装案

### PDF設定項目

PDF設定に任意項目として以下を追加する案。

- `download_monitor_id`

保存時:

- `absint` で整数化
- 空欄は `''` または `0` 扱い
- 既存PDF設定には自動付与しない
- Download Monitor側の投稿を更新しない

### レポート表示項目

管理画面の「ダウンロードレポート」セクション内に、PDF設定ごとの一覧表を表示する。

- PDF設定タイトル
- ショートコードID
- 言語
- 配信カテゴリ
- PDF URL
- Download Monitor ID または照合状態
- 合計ダウンロード数
- 最終ダウンロード日時
- 備考

### データ取得案

Download Monitor有効判定:

- `post_type_exists( 'dlm_download' )`
- かつ必要テーブルの存在確認
- `download_monitor()` 関数の存在確認は補助的に使う

合計ダウンロード数:

- `{$wpdb->prefix}dlm_downloads` が存在する場合、`download_id = DLM ID` の `download_count` を取得
- テーブルが無い場合は「取得不可」と表示

最終ダウンロード日時:

- `{$wpdb->prefix}download_log` が存在する場合、`MAX(download_date)` を取得
- `download_status IN ('completed', 'redirected')` を基本候補にする
- 該当無しは `-`

DLM投稿存在確認:

- `get_post( $download_monitor_id )`
- `post_type === 'dlm_download'`
- `post_status` が `publish` 以外の場合は備考に状態表示

### 未設定・不一致時の表示

- DLM ID未設定: `未設定`
- DLM投稿が存在しない: `ID未検出`
- DLMテーブルが無い: `Download Monitorテーブル未確認`
- DLM無効化中: `Download Monitorが有効ではありません`
- ダウンロード数未取得: `取得不可`

## 実装リスク

### Download Monitor無料版で取得できる範囲

公式プラグインページではダウンロード管理・追跡が基本機能として説明されている。公式KBとソース上も、無料版の本体にログテーブル、レポートテーブル、Reports REST APIが含まれている。

したがって、合計ダウンロード数と最終ダウンロード日時の読み取りは有料機能に依存しない見込み。

ただし、Enhanced Metricsなど有料拡張でログ削除や高度な分析機能が追加されるため、詳細分析や長期ログ保持前提の機能は有料拡張や設定の影響を受ける可能性がある。

### Download Monitorが無効化されている場合

`dlm_download` 投稿タイプやDLM関連関数が存在しない可能性がある。

対応:

- レポートセクションは表示する
- 「Download Monitorが有効ではないため、ダウンロード数を取得できません」と表示
- PDF設定やDCJ側処理には影響させない

### PDF URLとDownload Monitor項目が一致しない場合

手動ID方式ではPDF URLの不一致は集計自体の障害にはならない。

ただし管理者の確認用に、将来的には「DCJ側PDF URL」と「DLM側代表ファイルURL」が違う場合に備考表示する案がある。

初回はURL自動照合を避け、ID未設定またはID指定ミスだけを明示する。

### 既存PDF設定24件への影響

手動ID欄を任意項目として追加するだけなら、既存24件は未設定として表示される。

既存のPDF設定ID、PDF URL、メール本文、配信カテゴリ、ショートコードIDを変更しない限り、破壊的影響はない。

### 実サイト表示への影響

管理画面内のレポート表示だけに限定すれば、実サイト上のショートコード表示・無料PDFフォーム送信・メール送信には影響しない。

## LocalWPで追加確認すべきこと

1. Download Monitorの実バージョンを確認する
2. DBに以下のテーブルが存在するか確認する
   - `wp_download_log`
   - `wp_dlm_downloads`
   - `wp_dlm_reports_log`
3. `wp_posts` に `post_type = 'dlm_download'` の投稿が存在するか確認する
4. `wp_posts` に `post_type = 'dlm_download_version'` の投稿があり、`post_parent` が `dlm_download` IDになっているか確認する
5. `dlm_download_version` の `_files` メタにPDF URLが入っているか確認する
6. Download Monitor管理画面の表示ダウンロード数と `wp_dlm_downloads.download_count` が一致するか確認する
7. `wp_download_log` の `download_status` が実環境で `completed`、`redirected`、`failed` のどれで記録されているか確認する
8. 24件のDCJ PDF設定とDownload Monitor IDを手動で対応表にできるか確認する
9. Download Monitorを一時的に無効化した場合、DCJ管理画面にエラーが出ない設計にする

## 結論

v1.8.0では、完全自動照合ではなく、PDF設定に任意の「Download Monitor ID」欄を追加し、管理者が手動入力したIDをもとに読み取り専用レポートを表示する方式が最も安全。

最小実装では、合計ダウンロード数と最終ダウンロード日時だけを取得し、未設定・未検出・DLM無効時は分かりやすい状態表示に留める。
